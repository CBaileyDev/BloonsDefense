Proposed Approaches — AiGoonTube (Hybrid + Apple Silicon M5-optimized)

Locked in so far: Seamless private hybrid (C) — excellent local text roleplay as the privacy foundation + paid cloud for photos & video. Local tier optimized for M-series Macs (M5 and recent M4/M3 with 16-32GB+ unified memory) using MLX for best speed/quality. Windows as future stretch goal.

My take: Hybrid + Mac-primary is the right bet. It plays to real strengths (MLX on Apple Silicon is legitimately good for local LLMs in 2026) and gives a credible "your fantasies never leave your machine" story that most web apps can't match. The hard parts (NSFW-tolerant image/video providers, adult payments, local video being unrealistic) are the same across approaches.

1

Tauri + MLX-first Hybrid (Recommended)

Core: Lightweight native desktop (Tauri 2: Rust backend + webview). Local text via MLX (Apple-optimized) for responsive 13B–70B roleplay models on M5-class hardware. Cloud images/video gated behind subscription/credits.

Pros
  • Small footprint, native macOS feel, excellent battery/security story
  • MLX gives the best local tokens/sec and quality on target hardware — real "offline works great" experience
  • Easy to keep local mode completely air-gapped after model download
  • Future Windows port uses llama.cpp without rewriting the whole app
Trade-offs / Cons
  • Rust + MLX/llama bindings take more effort than pure web
  • Still need to hunt or self-host NSFW-friendly image/video APIs (mainstream ones are hostile to adult)
  • Local video gen remains impractical (even on M5)

High-level flow: Desktop UI (Tauri) ↔ Local MLX LLM (text/roleplay/memory) | Paid path → Cloud media gateway (Stripe + vetted providers) → Image/Video models

2

Electron + Ollama/llama.cpp Hybrid

Core: Electron desktop for faster rich UI development. Local inference via Ollama (easy install) or direct llama.cpp, still prioritizing Apple Silicon paths. Same hybrid cloud for media.

Pros
  • Much quicker to build complex roleplay features (branching, multi-char, lorebooks, UI polish)
  • Huge ecosystem — can adapt existing web RP frontends
  • Cross-platform (Windows) "for free" earlier
Trade-offs / Cons
  • Electron is heavy (memory, bundle size, "bloat" perception) — hurts the lightweight private companion vibe
  • Local perf still good on Mac but the overhead makes the "optimized for M5" story less compelling
  • Higher resource use even when "offline"
3

Tauri Hybrid + Early Local Image Ambition

Core: Same as #1, but invest early engineering in local image generation (MLX diffusion or converted Flux/SDXL models) so free tier includes text + some images offline. Video stays cloud-only.

Pros
  • Stronger "everything local" privacy claim — users can generate without any cloud for text + images
  • Differentiates even more from web apps
Trade-offs / Cons
  • Local image quality/speed on even M5 hardware is "good for a local model" not "paid tier competitive" for most users
  • Explodes app complexity, model download sizes, and support burden (prompt engineering, LoRAs, generation settings)
  • Delays the revenue-driving paid media features
  • Video still impossible locally at usable quality/speed

Hard realities that apply to all three

  • Video generation: Consumer-local high-quality video is not realistic in 2026 for a snappy app experience (slow, low-res, high VRAM). Plan on cloud for video from day one if you want it in paid tier.
  • NSFW cloud providers: Most big APIs have heavy restrictions or outright bans on adult/porn content. You will need to find tolerant ones (community hosts, specific endpoints, or self-hosted) and be prepared for them to change policies.
  • Payments for adult: High risk. Stripe works for some adult but requires approval, has high fees, and can be unpredictable. Crypto or specialized processors add UX friction. Chargebacks are common in this space.
  • Distribution & updates: Website DMG downloads + macOS notarization. No App Store. Need update mechanism (Sparkle, Tauri updater, etc.).
  • Safety / legal: Strong text filters + ToS that clearly puts responsibility on the user. No real-person non-consensual deepfakes. Age verification is mostly self-attestation + "18+ only" — robust ID checks kill the privacy appeal.
  • Model downloads: Users will pull multi-GB files. Need excellent UX, resume, recommended models, quantization choices, and storage management.
